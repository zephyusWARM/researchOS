# Deep Survey — Graph Privacy × Neural Relational Inference

Cutoff: 2026-09-29

## Executive correction

The earlier working formulation implicitly treated the canonical NRI spring benchmark as many trajectory records generated under one fixed latent graph. That is **not** how the original NRI synthetic generator works.

In the official NRI implementation, dataset generation loops over simulations. Each simulation calls `sample_trajectory`, and the spring simulator samples a fresh edge matrix inside that call. Thus, in canonical synthetic NRI, each trajectory/example has its own latent interaction graph.

This creates two distinct research settings that must not be conflated.

### Setting A — canonical / per-instance latent topology

[
x_i sim p(x_i mid G_i), qquad G_i 	ext{ varies across examples.}
]

Each trajectory has its own latent graph. The NRI encoder infers (q_phi(G_imid x_i)).

Privacy questions:
- training-record privacy: was trajectory (x_i) used to train the model?
- inference-input privacy: if a user supplies a private trajectory (x_*), does releasing the inferred graph posterior leak its latent relations?
- representation/output privacy: how much can an adversary infer about (G_i) from released embeddings, logits, or edge posteriors?

Record-level DP during training can protect the influence/participation of a training trajectory in learned parameters, but **training DP is not automatically a privacy mechanism for a fresh inference query (x_*)**.

### Setting B — fixed-system / shared latent topology

[
x_1,ldots,x_m sim p(xmid G), qquad G 	ext{ shared across observations.}
]

Multiple trajectories/windows/experiments are generated by the same physical or relational system.

Here (G) is a system-level/global property repeated across many records. Record adjacency on one trajectory and topology adjacency on (G) are genuinely different privacy notions.

This is the setting in which the statement “record-level DP is not topology privacy” is most direct.

It is scientifically natural for a fixed molecular system, infrastructure network, multi-agent system, or repeatedly observed dynamical system, but it requires a modified NRI benchmark or a fixed-system dataset rather than the canonical synthetic generator.

## 1. The field is not one problem: privacy unit taxonomy

“Graph privacy” is overloaded. At least five privacy objects matter.

### 1.1 Edge / relation privacy

Neighboring graph datasets differ by one edge/relation.

Typical goal: hide whether a pair of entities are connected.

Representative lineage:
- edge-DP mechanisms for graph statistics and graph learning;
- private graph diffusion;
- topology reconstruction defenses.

### 1.2 Node / entity privacy

Neighboring graphs differ by one node/entity and all incident information.

This is substantially stronger than edge privacy because one node can affect many edges and neighborhood computations.

Representative lineage:
- node-DP graph analysis;
- GAP node-level DP;
- DPAR;
- entity-level DP for relational learning.

### 1.3 Whole graph as one training record

A dataset contains many graphs, e.g. molecular graphs or patient graphs:

[
D={G_1,ldots,G_n}.
]

Graph-level DP in this literature often means changing/removing **one entire graph record**. This is not the same as hiding the topology inside a single graph.

This terminology is a major source of confusion.

### 1.4 Shared/global/latent topology privacy

The graph (G) is itself the sensitive system parameter that generates observations.

Examples:
- topology of a consensus network inferred from state/output trajectories;
- latent graph structure underlying graph signals;
- a fixed interaction network underlying repeated dynamical observations.

This is closer to system identification, Pufferfish/attribute/distribution privacy, and topology-adjacent DP than to ordinary record-level DP-SGD.

### 1.5 Inference-query privacy

A trained model receives a private graph/trajectory/query at inference time and outputs an embedding, prediction, or inferred topology.

Training DP protects training records; it does not by itself privatize a new inference input.

For canonical NRI, this is especially important because (G_i) is per-example: the sensitive topology may belong to the test query itself.

## 2. Genealogy: how the literature arrived here

### 2013 — node differential privacy for graphs

Node-DP graph analysis formalized adjacency by adding/removing a node with incident edges. The central technical problem is high sensitivity: one node can alter many graph statistics.

This establishes the first recurring lesson: **the privacy unit determines sensitivity.**

### 2014 — Pufferfish privacy

Pufferfish generalized privacy beyond a fixed neighboring-record relation. A mechanism is defined relative to:
- secrets to protect;
- pairs of secrets that should be indistinguishable;
- assumptions about data-generating distributions.

This is relevant whenever the private object is a latent/global system parameter rather than one database row.

### 2015 — topology itself as the DP secret

“Protecting Privacy of Topology in Consensus Networks” treats the state-transition/network topology as the private object.

It defines adjacency directly between nearby topology matrices (P,P'), rather than between agents’ input records. The released dynamical outputs are randomized so an observer cannot reliably distinguish nearby topologies.

This is a genuine formal ancestor for **topology-adjacent privacy**.

### 2018 — Neural Relational Inference

NRI introduces a variational latent variable representing an interaction graph and jointly learns:
- latent relations;
- system dynamics.

The canonical synthetic dataset, however, samples a graph per simulated example. This matters enormously for privacy semantics.

### 2020–2023 — private structure learning

Several lines privately recover structure from sensitive records:
- private Markov random-field structure learning;
- differentially private causal discovery;
- private Bayesian/network structure learning.

These works answer:

> Can we learn a structure while protecting the individuals/records used to learn it?

That is different from:

> Can we prevent the learned/released system from revealing the structure itself?

Call the first **private structure learning** and the second **structure-private learning**.

### 2021–2024 — attacks make topology leakage concrete

Link stealing, GraphMI/model inversion, group-property inference, and graph-property inference show that graph models can leak:
- individual links;
- reconstructed topology;
- group-level distributions;
- global properties of training graphs/data.

The attack target can be broader than the formal protected unit. A mechanism can satisfy edge-DP while still being a poor defense for a different target such as useful reconstruction of a large portion of graph topology.

This is not a contradiction of DP; it is a threat-model/protected-object mismatch.

### 2023–2025 — modern graph DP becomes architecture-aware

GAP, DPDGC, DPAR, private graph diffusion, and private relational learning all address graph-specific dependence rather than simply applying vanilla DP-SGD.

Key recurring mechanisms:
- perturb neighborhood aggregation;
- decouple propagation from private learning;
- bound degree/neighborhood influence;
- privatize graph diffusion;
- clip according to how often an entity appears across relations;
- derive privacy amplification under graph/relational sampling.

Eli Chien’s line is especially useful for the course because it progresses from multigranular topology protection to diffusion and then to relational/entity-level privacy.

### 2025–2026 — attack surface expands

Recent topology inference, graph unlearning attacks, graph pre-trained-model membership inference, and deeper GNN privacy analyses show that:
- privacy targets are increasingly global/structural;
- release surfaces include pretrained/foundation representations;
- message-passing depth and contraction affect privacy accounting;
- formal guarantee and empirical auditing need a matched target.

## 3. The key conceptual divide: private structure learning vs structure-private learning

### Private structure learning

Input:
[
D={x_1,dots,x_n}
]

Goal:
learn a graph/causal structure (G), while protecting participation or values of records (x_i).

Examples:
- private MRF structure learning;
- private causal discovery;
- private Bayesian network learning.

Here **structure is the target** and **records are private**.

### Structure-private learning

Input may be observations generated by (G).

Goal:
prevent the released mechanism from revealing (G) itself, or make nearby (G,G') hard to distinguish.

Examples:
- topology-private consensus networks;
- latent graph obfuscation;
- edge/node topology DP;
- topology-inference defenses.

Here **structure is private**.

### Why NRI sits exactly on the boundary

NRI explicitly outputs/internally represents the structure. Therefore:
- if trajectories are private but the inferred graph may be released, it resembles private structure learning;
- if graph relations themselves are sensitive, it becomes structure-private relational inference;
- if the graph belongs to a fresh test trajectory, it becomes inference-time privacy.

This three-way distinction is the main conceptual result of the survey.

## 4. Why the earlier “record-level DP is not topology privacy” claim needs qualification

The statement remains correct in **Setting B**, where many observations share one (G).

But it is not the whole story in canonical NRI.

### Canonical NRI

Each example has its own ((x_i,G_i)). If one complete trajectory is treated as one DP record, then record-level DP can limit what trained parameters reveal about that training example, including information statistically tied to its (G_i).

However, if the same private trajectory is later provided to the trained encoder and the model emits (q(G_imid x_i)), training DP does not hide the query’s topology from the recipient of that output.

So the sharper canonical-NRI question is:

> **Training privacy vs inference-time latent-topology privacy.**

### Fixed-system NRI

Many (x_i) share one (G). Then record-level privacy of individual trajectories does not directly specify privacy of (G), which is a repeated/global system property.

So the sharper fixed-system question is:

> **Individual-record privacy vs global topology privacy.**

## 5. Formalisms that may fit the fixed-system problem

### 5.1 Topology-adjacent DP

Define neighboring systems directly on graph parameters:

[
Gsim G'
]

for example by:
- one edge addition/deletion;
- one bounded edge-weight change;
- bounded matrix norm (|P-P'|le eta).

Then require a released randomized mechanism to have close distributions under (G,G').

Strength: directly expresses the desired topology secret.

Difficulty: changing one edge in nonlinear dynamics can alter a whole trajectory distribution, making sensitivity difficult or unbounded without stability assumptions.

### 5.2 Group DP

Treat all observations affected by a shared topology property as a group.

Problem: the effective group may be the entire dataset, causing privacy bounds/noise to degrade badly. It is a useful baseline, not necessarily the right solution.

### 5.3 Pufferfish privacy

Define:
- secret (S): edge exists vs does not exist, or topology belongs to class A vs B;
- discriminative pairs;
- admissible trajectory-generating distributions.

Strength: directly handles correlations and generative assumptions.

Difficulty: requires explicit modeling assumptions.

### 5.4 Attribute / distribution privacy

Treat the shared graph/topological property as a global attribute/distributional property.

Strength: conceptually aligned with a signal repeated across many records.

Difficulty: mapping a combinatorial graph to a tractable distribution/property-privacy mechanism is nontrivial.

## 6. Formalisms that may fit canonical NRI

### 6.1 Training-record DP

Each complete simulation trajectory is one record. Per-example gradient clipping/noising can in principle provide a training-record guarantee if the implementation/accounting is valid.

This protects the influence of a trajectory on learned parameters.

It does **not** by itself privatize the model’s response to a fresh private trajectory.

### 6.2 Output / query DP at inference

Randomize the inferred edge posterior, latent representation, or prediction so nearby private inputs induce close output distributions.

Need to define neighboring trajectories or neighboring latent structures.

Potentially cleaner for canonical NRI because the topology is per query.

### 6.3 Local DP / privatized trajectories

Privatize observations before they reach the relational inference model.

Strength: strong input-side privacy.

Risk: NRI relation identifiability may collapse quickly because relation recovery is already statistically demanding.

## 7. Candidate experiments after the correction

### Project A — canonical NRI: inference-time topology privacy

Question:
How much must an inferred edge posterior be randomized to reduce topology recovery while retaining useful dynamics prediction?

Setup:
- standard per-example NRI spring benchmark;
- train standard NRI;
- release edge posterior / sampled edges / decoder prediction under controlled perturbations;
- attack target: (G_i) of the query;
- metrics: edge AUROC/accuracy, prediction MSE, posterior calibration.

Formal extension:
derive query/output adjacency and a valid DP mechanism if feasible.

Strength:
faithful to canonical NRI.

Risk:
without a formal mechanism it becomes an empirical obfuscation project rather than a DP project.

### Project B — fixed-system NRI: record privacy vs shared-topology privacy

Question:
If many trajectories share one fixed (G), does trajectory-record DP meaningfully reduce recoverability of (G)?

Setup:
- modify spring simulator to sample one graph and generate many initial-condition trajectories from it;
- train/infer a shared topology;
- compare non-private and record-level DP training;
- vary number of trajectories (m), epsilon, trajectory length, graph density.

Metrics:
- edge AUROC;
- trajectory prediction MSE;
- membership inference for individual trajectories;
- topology inference.

Interpretation:
If record membership leakage falls while topology remains recoverable, that demonstrates privacy-granularity mismatch, not a DP violation.

Strength:
the cleanest conceptual privacy-granularity experiment.

Risk:
not the canonical NRI benchmark; must clearly label the modified system-identification setting.

### Project C — formal topology DP for nonlinear relational inference

Question:
Can one derive a useful sensitivity/privacy bound when neighboring dynamical systems differ by one interaction edge?

Strength:
most theoretically original.

Risk:
may become a full theory project; nonlinear dynamics can make global sensitivity difficult.

For a course project this should be a stretch goal, not the minimum viable contribution.

## 8. Direct-precedent red-team

Targeted searches were run for combinations of:
- Neural Relational Inference + differential privacy;
- latent graph inference + differential privacy;
- interaction graph + privacy + trajectories;
- topology inference + dynamical systems + privacy;
- latent relational structure + privacy.

No primary paper was found in this search pass that directly formulates **formal topology privacy for Kipf-style NRI or a close neural latent-interaction model**.

This is a **gap signal, not proof of novelty**.

Dense adjacent literatures exist:
- topology privacy in control systems;
- latent graph obfuscation;
- private causal/graph structure learning;
- graph edge/node DP;
- inference-time/privacy attacks on GNNs;
- property privacy.

Any final novelty claim must therefore be narrow and phrased around the exact NRI setting, release surface, and protected object.

## 9. Survey verdict

### What is already crowded

- generic “DP for GNNs”;
- generic node/edge privacy;
- generic membership inference against GNNs;
- generic graph unlearning/privacy;
- generic private structure learning;
- broad “graph topology can leak.”

### What remains plausibly interesting

1. **Canonical NRI: training privacy vs inference-time privacy of per-instance latent topology.**
2. **Fixed-system NRI: individual-trajectory privacy vs shared/global topology privacy.**
3. **Formal topology-adjacent privacy for nonlinear learned relational dynamics.**

### Current recommended course framing

Do **not** start by promising a new topology-DP theorem.

First build the two-setting benchmark and answer a falsifiable privacy-granularity question. If the empirical frontier is nontrivial, add a formal topology-aware mechanism only if the sensitivity analysis closes.

The most important deliverable for instructor discussion is therefore a diagram/table that states, for every experiment:

[
oxed{	ext{private object} ightarrow 	ext{adjacency} ightarrow 	ext{release surface} ightarrow 	ext{attacker} ightarrow 	ext{metric}}
]

If any one of those five is missing, the privacy claim is underspecified.
